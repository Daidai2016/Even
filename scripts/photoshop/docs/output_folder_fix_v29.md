# 大画面批量输出助手 V29：输出目录检查修复

使用入口：在目标 Photoshop 中选择“文件 > 脚本 > 浏览”，运行 `scripts/photoshop/jsx/large_format_batch_output_v29.jsx`。仍按原流程选择输入文件夹和输出位置。

按用户要求，批量脚本仅保留最新 V29，旧 V28 文件已删除。V29 沿用原有尺寸、像素、分辨率、色彩、TIFF/JPG 保存参数、输出命名与报告格式。

## 修复内容

V28 的写入检查在创建测试文件后，使用 `File.opened` 判断是否需要关闭。但本机 Photoshop ExtendScript 返回该属性为 `undefined`，导致跳过关闭。在 Windows 上，测试文件保持打开时无法删除，检查因此把可写目录误报为“无法写入”。

V29 根据 `open()` 的成功返回值执行关闭，再清理本次测试文件。报告写入异常时的同类关闭判断一并修正。测试文件命名会避开已有文件。

检查失败仍会在处理图像前停止。提示区分创建、写入、关闭和清理失败，并显示系统返回的原因；无法清理时显示测试文件路径。真实权限不足仍需选择可用目录或修复该目录的访问权限。

## 验证结果

2026-11-04，在本机 Windows、Photoshop 27.11.0 中通过 COM 调用实际 ExtendScript 函数验证：

- 在可写目录重现 V28 返回失败，确认 `File.opened` 为 `undefined`。
- V29 在英文、中文、含空格、含 `%` 的四种目录中检查成功，测试文件全部关闭并清理。
- 四种目录均成功写入并读回中文 UTF-8 报告，已有报告的覆盖保护有效。
- Node 回归检查通过：完整 JSX 语法解析；模拟打开、写入、关闭、删除失败及写入抛出异常；报告写入失败清理与已有报告保护。运行方式：`node scripts/photoshop/examples/test_output_folder_v29.js`。

本次真机验证覆盖输出目录检查和文本报告写入，未运行完整图像生产批次。用户原输出目录、网络共享目录和 macOS 尚未实测；真实拒绝访问、磁盘写入失败等分支通过模拟验证。
