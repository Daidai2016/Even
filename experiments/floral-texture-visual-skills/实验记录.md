> 当前状态（`2026-08-23`）：根据用户对实际测试质量的明确评审，`floral-texture-motion-poster` 动态海报 Skill 已从源目录、可安装插件和本机安装版本中删除。下文动态测试内容仅作为失败证据保留，不再作为可调用能力；静态 `floral-texture-poster` 继续保留。

## 目标

建立两项边界明确的初始示例能力：

1. 把用户提供的花卉图片转译为极简几何、纸张颗粒、丝网印刷和几何渐变风格的静态视觉素材，并执行生成前参数确认及生成后 PS/AI 完稿。
2. 等待用户再次上传已完成 PS/AI 后期的静态母版，再延展为固定镜头、背景不变、花苞从底部生长、原位旋转一周、缓慢绽放、轻微摆动和文字渐显的动态海报。

预期场景包括品牌 KV 试验、文化活动海报、社交媒体竖版动态海报和后期排版用主视觉素材。

## 规则来源与版本

- 规则来源：用户在 ChatGPT 会话“归纳肌理提示词”中确认的设计逻辑，以及 `2026-08-23` 本次任务提供的四组静态 Prompt 与动态效果说明。
- 静态配色能力：分别确认原图花瓣渐变、目标花瓣渐变、目标花茎渐变和目标花蕊颜色，支持任意自然语言颜色、色值、色卡或多段渐变；红色、橙红色、淡紫色和橙黄色只作为示例；默认干净白色背景、无文字。
- 动态能力：固定镜头、底部快速生长、花苞原位完整旋转 `360°`、缓慢绽放、文字同步渐显、轻微摆动、背景不变、无人物口播。
- 当前规则版本：`0.3.1`；前一版为 `0.3.0`。

## `0.2.0` 流程修订

### 静态流程

```text
参考图分析
→ 对话窗口补齐关键参数
→ 生图与筛选
→ Photoshop / Illustrator 后期
→ 目标尺寸质量检查与导出
→ 用户确认处理完成
```

关键参数不全时必须暂停生图并集中询问；只有生成结果而未完成约定的 PS/AI 后期时，状态只能标记为“生成素材完成，后期未完成”。

### 动态流程

```text
用户再次上传 PS/AI 完稿母版
→ 检查静态母版与动态参数
→ 首尾帧和分层资产
→ 动态生成或分层制作
→ 文字与逐帧后期
→ 最终视频、首尾帧与工程文件
```

首次生图不得自动作为动态母版。没有用户再次上传的静态完稿，动态 Skill 必须停在“等待上传静态完稿母版”。

## `0.3.0` 参数与风格范围修订

用户进一步明确：红色、橙红色、淡紫色和橙黄色不是封闭的颜色选项，只是提示词示例。静态 Skill 的颜色输入改为四项彼此独立的开放参数：

1. 原图花瓣的渐变过渡色彩。
2. 转化后花瓣的目标渐变过渡色彩。
3. 转化后花茎的目标渐变过渡色彩。
4. 转化后花蕊的目标颜色。

四项均支持自然语言颜色、色值、色卡和多段渐变。花心、蒴果、花托、叶片及枝条的色彩与简化方式作为补充参数；未指定时保留参考图的识别色关系，但必须统一几何化。

“极简主义平面几何插画风格”的作用范围同步扩展为完整花卉主体，而不是只处理花瓣。花瓣、花蕊、花心或蒴果、花茎、花托、叶片和枝条必须使用同一套平面几何、透明叠印、纸张颗粒和丝网印刷语言；几何花瓣与写实摄影花茎或花心混合视为失败。

术语统一：原提示词中的“花径”按语境规范为“花茎”。

## `0.3.1` 默认保色规则修订

用户在查看 v002 后指出：风格转绘的默认目标应是“只改变风格，不改变色彩风格”。`0.3.0` 把目标花瓣、花茎和花蕊颜色均设为生成前必填，容易让 Skill 在用户没有主动要求时也进入换色流程，因此修订如下：

- 新增 `color_mode`：默认 `preserve-source`；只有用户明确提出改色、提供目标颜色或要求配色变体时，才使用 `recolor`。
- 保色模式逐部位继承原图色相、明度、饱和度、冷暖、对比、内部色差和渐变方向，只改变几何造型、透明叠印、纸张颗粒和丝网印刷语言。
- 保色模式下，目标花瓣、花茎、花蕊及其他部位颜色不是缺失参数，不得为此暂停、追问或主动建议换色。
- 换色模式继续支持四项开放参数，但只处理用户明确指定的换色部位；其他部位保留原色。
- 质量检查新增“无授权色彩漂移”：如果观者首先感知到换了一套颜色，保色转绘即判定失败。

## 预判失败模式

- 双花数量、上下位置或交叉花茎被改变。
- 虞美人宽薄花瓣、褶皱、蒴果或放射状花蕊丢失。
- 几何概括过度，花瓣变成随机矩形堆叠。
- 纸张颗粒变成均匀噪点，丝网印刷变成脏污或低清。
- 白色背景变灰、变色、出现复杂场景或多余元素。
- 动态中花苞没有从底部生长、旋转不是原位完整一周、突然换花、背景呼吸、镜头漂移或边缘闪烁。
- 生成模型改写文字，或出现人物、口播人物、假 Logo 与水印。

## 晋级决定

当前证据不足以宣称静态 Skill 为“已验证正式能力”，因此静态 Skill 与本地插件继续保留 `initial-example` 状态。动态 Skill 已因实际测试质量不达标而删除；若未来重新研究动态能力，必须作为新实验从分层资产、运动方法和独立人工评审重新开始，不得沿用已删除 Skill 的可用性结论。
