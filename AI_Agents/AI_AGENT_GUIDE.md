## 三、总体工作流程

Codex Design 推荐使用以下 AI 协作方式：

```text
项目需求
   ↓
OpenAI Codex 项目主控
   ↓
编程与分析模型提供辅助意见
   ↓
代码、文档或提示词人工审核
   ↓
视觉模型生成创意或素材
   ↓
Photoshop / Illustrator 人工审核与生产
   ↓
Git 检查、提交和发布
```

核心原则：

1. OpenAI Codex 是本地项目主控。
2. 其他编程模型主要提供分析和第二意见。
3. 视觉模型只提供创意、参考图或素材。
4. AI 输出不得直接视为最终生产文件。
5. 所有代码在执行前必须检查。
6. 所有视觉内容必须经过 Adobe 人工审核。
7. 所有仓库修改必须进入 Git 工作流。
8. 所有敏感凭据必须保存在安全的本地环境中。
9. 不允许多个 AI Agent 同时自动修改同一个文件。
10. 不允许视觉模型直接决定最终印刷或交付参数。

# 四、项目主控

## OpenAI Codex

### 项目角色

```text
唯一项目主控
```

OpenAI Codex 负责：

- 读取和理解本地仓库
- 遵守 `AGENTS.md`
- 遵守 `CODING_RULES.md`
- 创建和维护 PowerShell 工具
- 创建和维护 Adobe JSX 脚本
- 检查项目目录结构
- 维护 VS Code 工作区配置
- 维护 Git 工作流工具
- 分析错误日志
- 执行代码审查
- 协助管理 MCP 配置
- 维护环境检查工具
- 维护工作区恢复工具
- 协助准备 Git 提交

### 当前使用入口

| 入口 | 项目状态 | 说明 |
|---|---|---|
| Codex CLI | 使用 | 在项目终端中运行 |
| Codex VS Code 扩展 | 使用 | 主要本地开发入口 |
| Codex 桌面应用 | 可用 | 适合独立任务和项目管理 |
| Codex 云端任务 | 可选 | 需要明确授权 |
| OpenAI API | 可选 | 仅在存在明确自动化需求时使用 |

### 仓库权限

Codex 可以在用户授权后：

- 查看仓库文件
- 创建新文件
- 修改现有脚本
- 执行语法检查
- 执行非破坏性检查命令
- 运行项目环境检查
- 协助准备 Git 提交
- 分析 Git 状态
- 调用经过确认的 MCP 工具

Codex 不得未经确认：

- 删除用户设计文件
- 覆盖重要生产文件
- 执行 `git reset --hard`
- 执行 `git clean -fd`
- 执行强制推送
- 自动发布未经检查的代码
- 把敏感凭据写入仓库
- 修改未经确认的 Adobe 生产文档
- 绕过项目安全发布工具

### Git 管理

项目中的 Git 工具包括：

```text
tools/git_status.ps1
tools/git_sync.ps1
tools/git_publish.ps1
```

Codex 可以帮助分析 Git 状态，但不得绕过安全规则执行破坏性操作。

# 五、编程与分析 Agent

编程与分析 Agent 用于：

- 提供第二意见
- 解释代码
- 分析错误
- 比较实现方案
- 优化提示词
- 审查算法
- 生成参考代码
- 总结技术资料
- 阅读长文档
- 分析图片或界面截图

这些 Agent 默认不是本地仓库主控。

除非以后建立经过审核的 API、MCP 或官方扩展集成，否则其输出应由用户复制回 Codex Design，再由 Codex 根据项目规则整理。

### VS Code 管理规则

Gemini Code Assist 属于可选辅助工具，不是 Codex Design 项目主控。

同时启用多个 AI 编程扩展可能造成：

- 快捷键冲突
- 自动补全冲突
- 同一文件被多个工具建议修改
- 代码上下文重复发送
- 网络和代理连接冲突
- 修改来源难以追踪

推荐工作模式：

```text
主要开发：OpenAI Codex
辅助分析：Gemini
```

不要让多个 Agent 同时自动修改同一文件。

## Midjourney

### 项目角色

```text
视觉概念、风格探索和素材生成
```

### 当前项目入口

```text
主要入口：Midjourney 网页 Create 页面
辅助入口：Discord
VS Code：不使用
API：当前项目不建立默认接入
```

Midjourney 不属于本地编程 Agent，也不负责管理 Git 仓库。

它不得：

- 自动读取整个本地仓库
- 自动修改 PowerShell 脚本
- 自动修改 JSX 脚本
- 自动执行 Git 操作
- 自动修改 Photoshop 或 Illustrator 文档
- 获得本地生产目录的完全访问权限

### 适合任务

Midjourney 适合：

- 品牌视觉方向探索
- 构图草案
- 海报概念图
- 场景气氛设计
- 角色或物体概念
- 风格参考
- 灯光参考
- 色彩氛围参考
- 背景素材
- 纹理素材
- 图像提示词测试
- 系列视觉一致性探索
- 设计提案参考图

### 不适合直接完成的任务

Midjourney 结果不得直接视为：

- 最终标志文件
- 最终矢量文件
- 最终文字排版
- 最终包装刀版
- 最终印刷文件
- 最终大画面输出文件
- 最终品牌标准文件
- 最终可编辑分层文件
- 最终客户交付文件

### Adobe 生产流程

Midjourney 素材必须经过：

```text
Midjourney 生成
   ↓
人工筛选
   ↓
检查细节与版权风险
   ↓
Photoshop 修图、合成和色彩处理
或
Illustrator 重绘、排版和矢量化
   ↓
生产尺寸和输出规范检查
   ↓
人工确认
```

### 重点检查内容

使用 Midjourney 素材时必须检查：

- 手部、面部和物体结构
- 透视关系
- 光影方向
- 重复纹理
- 不合理连接
- 伪文字
- 品牌标志
- 商标和受保护元素
- 人物肖像授权
- 素材商业使用条件
- 图像分辨率
- 色彩模式
- 最终输出尺寸

### API 管理

当前 Codex Design 项目不把 Midjourney API 作为基础工作区能力。

在官方能力、授权方式、费用、数据隐私和项目需求没有单独确认前：

```text
不建立 Midjourney API 脚本
不在仓库中保存 Midjourney 凭据
不安装来源不明的 Midjourney API 代理
不使用非官方自动化服务绕过平台规则
```

即使以后建立正式 API 或自动化入口，也必须：

1. 先确认官方授权方式。
2. 单独建立安全设计方案。
3. 使用系统环境变量保存凭据。
4. 对日志进行脱敏。
5. 设置费用和调用限制。
6. 不允许自动发布生成结果。
7. 所有结果仍进入 Adobe 人工审核。

# 七、Adobe 最终生产流程

所有视觉 Agent 输出最终都必须进入 Adobe 人工审核。

标准流程：

```text
AI 生成创意或素材
   ↓
保存原始生成结果
   ↓
记录生成工具和用途
   ↓
人工筛选
   ↓
Adobe Photoshop
或
Adobe Illustrator
   ↓
构图、修图、排版和矢量化
   ↓
颜色、字体、尺寸和分辨率检查
   ↓
```

## Illustrator MCP 边界

Illustrator MCP 属于项目自动化实验能力。

普通环境检查只确认：

```text
配置状态
令牌变量
实时端口
```

三层状态示例：

```text
配置状态：adobe_illustrator 已配置并启用
令牌变量：ADOBE_ILLUSTRATOR_MCP_BEARER_TOKEN 已存在
实时端口：18412 正在监听
```

Illustrator 未启动时可以显示：

```text
实时端口：18412 当前未监听
提示：Illustrator 可能未启动或 MCP 尚未开启
```

Illustrator 未启动属于提示或警告，不应直接判定配置失败。

真正读取 Illustrator 文档时，应通过 Codex 执行只读测试。

普通 PowerShell 脚本不得：

- 创建 Illustrator 图形
- 删除 Illustrator 对象
- 修改当前文档
- 保存当前文档
- 执行不可验证的界面操作
- 向 MCP 发送会改变文档的请求

# 八、AI 输出进入仓库的规则

AI 网页或客户端生成的内容，不应自动进入 Git 仓库。

进入仓库前必须确认：

1. 内容与当前项目任务相关。
2. 没有客户隐私信息。
3. 没有账号凭据。
4. 没有真实 API Key。
5. 没有真实 Token。
6. 没有明显版权或授权风险。
7. 文件名称符合项目规则。
8. 大型设计文件由 Git LFS 管理。
9. 代码已经通过语法检查。
10. 视觉文件已经经过人工审核。
11. 生成内容没有伪造品牌或受保护标志。
12. 文件用途和来源可以追踪。

# 九、API 和凭据安全

## 基本规则

以下内容只能保存在安全的本地环境中：

```text
API Key
Token
账号密码
私钥
客户端登录凭据
```

允许的保存位置：

- Windows 用户环境变量
- Windows 凭据管理器
- 对应 AI 客户端的安全存储
- 不受 Git 管理的本地配置
- 企业批准的密钥管理系统

禁止保存到：

- Markdown 文档
- PowerShell 脚本
- JavaScript 或 JSX 文件
- JSON 配置
- VS Code 任务文件
- Git 提交信息
- 环境检查报告
- 截图
- 聊天记录
- README

---

## 环境变量规则

文档可以记录环境变量名称，例如：

```text
PROVIDER_API_KEY
MODEL_ACCESS_TOKEN
```

文档不得记录：

```text
PROVIDER_API_KEY=真实值
MODEL_ACCESS_TOKEN=真实值
```

脚本读取环境变量时，只能使用类似：

```powershell
$env:PROVIDER_API_KEY
```

环境检查只能确认：

```text
变量已存在
变量未配置
```

不得输出：

```text
变量真实值
变量长度
变量开头字符
变量结尾字符
经过编码的变量值
经过哈希的变量值
```

即使只显示部分字符，也可能造成凭据泄露。

---

## API 启用原则

网页或客户端能够完成的工作，不必为了技术展示而强制接入 API。

只有满足以下条件时才启用 API：

1. 存在明确、重复的自动化任务。
2. 网页操作无法稳定完成。
3. 已确认费用和调用限制。
4. 已确认数据隐私规则。
5. 已建立错误处理。
6. 已建立调用日志脱敏。
7. 已获得用户明确授权。
8. 已确认不会把密钥提交到 Git。
9. 已确认服务条款允许该自动化方式。
10. 已建立停止和撤销机制。
