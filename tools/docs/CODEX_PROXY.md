# Codex 代理环境配置与恢复

日常入口位于桌面 `Even Codex Design/01_开发工具`。先启动本机代理软件，再双击「Codex 代理环境配置」。

## 配置过程

1. 读取当前系统代理、进程及持久化环境变量、Git 配置；仅在配置不能提供可达端口时枚举已知代理软件的真实监听端口。不硬编码代理端口，不改系统、Git 或代理软件设置。
2. 显示监听进程和端口，通过选定的本机 HTTP 代理发送 HEAD 请求，检测 ChatGPT 与 OpenAI API 的 HTTPS CONNECT、TLS 和响应头，不下载网页响应体。证书验证保持开启，不携带账号密钥、不回退直连；已配置代理的 HTTPS 检测失败时停止，不静默切换代理。API 的匿名 401 仅代表网络可达。
3. 预览旧值与拟写入值，只更新 `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY`；保留其他配置，合并原有 `NO_PROXY` 绕过名单。现有 `ALL_PROXY` 或误拼的 `NO_PR0xY` 只提示，不自动删除。
4. 输入“确认”才写入，其他输入取消。已有文件在同目录原子替换时生成 `.env.bak.北京时间-随机后缀`，并校验写入字节；预览后文件变化则停止。内容相同不写入、不重复备份。

默认目标为当前用户目录下的 `.codex/.env`；如使用自定义 Codex 主目录，需显式通过 `-OutputPath` 指定其 `.env`。支持 Windows PowerShell 5.1，需要 `Get-NetTCPConnection` 和 `curl.exe`。仅支持不含代理认证信息的本机 HTTP／混合端口；SOCKS 专用端口、远程代理和 PAC 解析不在自动写入范围内。

代理来自本机实时检测，模板仅作说明：

```dotenv
HTTP_PROXY=http://127.0.0.1:<当前HTTP端口>
HTTPS_PROXY=http://127.0.0.1:<当前HTTP端口>
NO_PROXY=localhost,127.0.0.1,::1
```

`HTTPS_PROXY` 的值仍以 `http://` 开头，因为这里连接的是本地 HTTP CONNECT 代理。无需添加空的 `ALL_PROXY=`。`NO_PROXY` 用字母 O，不是数字 0；它主要保障本机连接，不是修复所有重连问题的开关。

## 重启验证

保存工作，正常关闭全部 VS Code 窗口及独立 Codex 客户端，再重新打开实际使用的客户端。工具不会强制结束当前会话。

新建对话，测试简单回复和一次稍长的连续输出，观察是否仍出现重连 1/5～5/5。端口监听、网页访问和 TLS 检测通过不等于登录、WebSocket 或长时间流式连接正常；也不能单凭文件写入成功证明当前客户端已加载该文件。不同客户端的环境继承和加载行为可能不同。

若仍重连，记录发生时间并检查 Codex 输出日志中的连接失败、超时、403/429 或认证错误，再区分代理上游、客户端环境加载、登录与服务端问题。不要通过关闭 TLS 验证或不断增加重试次数来掩盖问题。

## 恢复

双击「Codex 代理环境恢复」，从列表选择需要的 `.env.bak.*` 备份，查看代理内容并输入“确认”。恢复会还原整个备份文件，包括当时的其他配置，并先备份当前 `.env`；无需网络可用。恢复后再次完全退出并重新打开客户端。

也可在资源管理器打开用户目录下的 `.codex`，先另存当前 `.env`，再用明确选定的 `.env.bak.*` 备份替换它。不要删除历史备份。

## 自动化与兼容性

入口为 `tools/create_codex_env.ps1` V1.1.0：

- `-Preview -NoPause`：检查并预览，不写入。
- `-Apply -NoPause`：仅在操作者已明确批准后使用；仍检测、备份并校验。
- `-RestoreBackupPath <完整备份路径>`：仅接受目标 `.env` 同目录、同名前缀的历史备份；默认仍需确认。
- `-OutputPath <路径>`：指定目标文件，可用于隔离测试。
- `-ProxyUri <本机HTTP地址>`：显式指定代理，失败不自动换地址。
- 旧 `-Force` 参数保留兼容，但不能绕过确认；旧调用 `-Force -NoPause` 在需要更新时仅预览，退出码 0 表示检查完成，**不表示已写入**。

Skills 同步入口沿用上述兼容调用，检测到需更新时应另开配置快捷方式确认。旧工具归档在 `tools/stable/`，其中脚本仅供比对；真实用户 `.env`、凭据与本机备份不提交到仓库。
