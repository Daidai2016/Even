# 视觉任务与生图提示编写指南

版本：2.0 / 2026-09-10
依据：[OpenAI Image prompting](https://developers.openai.com/api/docs/guides/image-prompting)，2026-09-10 核对。

## 1. 定位与使用

本文件维护视觉任务的需求整理方式与生图提示模板。直接描述要得到的成果，不要求角色设定、固定契约或固定章节。简单任务可直接使用一句话或一段提示；复杂任务按需分段，选择最便于阅读和修改的格式。

官方指南是生图提示写法的依据；本仓库的品牌保护、参数硬锁、中文排印和生产验收是工作台约束。用户明确要求优先；模型特定设置以当前工具实际支持为准，不因文档更新自动切换模型。

- 按分类入口读取[共享视觉规范](平面设计生图与动态视觉规范.md)及匹配的 Skill，只加载当前任务所需路由。
- 生图、参考创作和编辑的执行与文件验收沿用[生图生产路由](routes/production/image-generation.md)。本文件不复制工具操作流程。
- 非生图设计任务直接说明目标、准确内容、参考用途、约束和交付标准；不强制写成生图 Prompt。
- 动态任务在已确认静态设计上追加时长、帧率、动作、节奏、循环与镜头许可，沿用动态路由；静态图像 API 设置不适用于视频。

## 2. 编写原则

1. **先写结果。** 说明做什么图、给谁看、用在哪里，写清主体、画幅、构图和关键位置；不要求先输出设计师身份或完整分析。
2. **写可见细节。** 用具体形态、材质、光线、颜色和媒介表达风格。需要照片效果时明确写实目标，并交代取景、尺度和纹理；相机参数只是外观线索，不保证物理模拟准确。
3. **动作写清关系。** 人物或对象需要哪些部位入画、朝向哪里、如何握持或接触其他物体，应按任务明确；不无故新增姿态、对象或布局。
4. **准确文字单独标明。** 用引号包住原文，说明位置、排印和出现次数；必要时逐字澄清特殊拼写。说明不添加额外文字，生成后逐字核对可读性、数字及标点。
5. **编辑分清改与不改。** 指定区域、对象和变化，明确身份、形状、构图、配色、光线、标签等保留项。禁止项只针对本轮实际风险，不把通用负面词库整段附加到每个提示。
6. **参考逐张分工。** 用编号或文件名区分底图、主体、构图、风格和待合成资产，说明只采用哪些属性以及组合关系。只有参考用途的图不能替代唯一底图。
7. **逐轮收敛。** 使用已确认输出作为下一轮输入，每轮修改一个问题或一组相关问题，重申关键保留项并检查结果。不要靠不断追加重复措辞代替失败诊断。
8. **格式服务维护。** 自然段、分段指令、标签或结构化字段均可；不宣称特殊语法更有效，不强制英文或长提示。默认使用中文，保留准确专名和用户指定语言。

以上是对官方原则的工作台应用。完整后期步骤、保存路径、审核记录不必塞入图像提示；需要交付时单独提供。

## 3. 约束、文字与设置

- 沿用[参数硬锁](shared/parameter-lock.md)：用户指定的底图、主体、配色、文字、Logo、尺寸及输出要求不得被默认值覆盖。冲突按[冲突处理](shared/conflict-resolution.md)解决。
- 只追问会实质改变主体、准确内容、授权范围或关键交付规格的缺口；其余使用最小假设，不重复询问已有信息。
- 用户要求图内文字时允许直接生成并逐字验收。需要标准 Logo、精确字体、可编辑排字或生产级一致性时使用官方资产及可控后期；错误文字不可作为合格结果。详细排印见[字体规则](shared/typography.md)。
- 提示描述画面和目标画幅；`model`、`size`、`quality`、`background`、格式等实际 API 设置单列，仅在工具支持时使用。网页、Codex 工具与 API 不共用一套参数。
- 请求透明背景不等于文件具有 alpha；写下尺寸不等于输出达到该尺寸。打开实际文件验证，不能把放大或改 PPI 当作原生细节通过。
- 生成编辑不能保证区域像素完全不变；有此要求时，在原图上可控合成已批准修改，并对保护区作差异核验。

## 4. 四类可裁剪模板

以下是自建示例，不是官方固定格式。只填写相关字段，删除无关句子；不得用模板默认值替换已确认需求。

### 新建图像

```text
为{用途/受众}生成{图像类型}，主体是{主体与动作}。
画面采用{画幅与构图}，{关键元素位置、尺度及留白}。
使用{视觉媒介、材质、光线、颜色等可见特征}。
{仅在需要文字时：在指定位置显示“准确原文”，出现指定次数，采用指定排印，不添加其他文字。}
{本任务必要的约束。}
```

### 参考创作

```text
创作{目标主体与用途}。图1只参考{配色/材质/构图等属性}，图2只参考{明确属性}。
新画面为{主体、动作、位置、画幅和可见细节}。
保留{用户指定项}；不引入参考图中的{不需要的主体、文案或品牌元素}。
```

### 局部编辑

```text
以图1为唯一底图，只把{区域内的对象/属性}改为{目标变化}。
保持{身份、几何、位置、画幅、颜色、光线、文字和周围对象等本轮保留项}。
图2仅提供{辅助参考用途，如有}。修改与原图的{透视、光线、边缘}自然衔接。
```

### 多图合成

```text
图1是底图，图2提供{待插入主体}，图3提供{风格参考或品牌资产}。
将{来源对象}放入图1的{位置}，按{相对尺度、透视、光线和遮挡关系}融合。
保持{底图保护区域、主体身份、准确标签等}；图3只用于{明确用途}。
```

### 准确文字写法示例

```text
上方标题为“春日花园”，只出现一次，居中、清晰的中文黑体效果；下方日期为“2026.04”，只出现一次。不添加其他文字。主体和标题区互不遮挡。
```

这是排印外观提示，不保证具体字体文件或文字可编辑。用户指定字体或后期留白方案时，按原要求执行。

## 5. 输出与验收

用户只要提示词时直接提供可用提示，必要的工具设置和待确认项另列；无需先展示分析、角色或契约。完整设计方案按实际交付阶段补充视觉判断、后期制作及验收，不机械填空。

交付前核对：

- 目标、主体、构图与全部硬锁是否满足，是否擅自新增内容。
- 参考图分工是否正确，底图及保护区是否保留。
- 文字、Logo、人物、产品和数据是否准确，排印是否可读。
- 已执行的输出尺寸、格式、透明度、可编辑性是否有实际文件证据。
- 当前状态是提示词完成、生成素材完成、后期完成还是导出已核验；尚未执行的环节明确说明。

本次指南修订不构成视觉能力验证。新方法与样例的生产可用性仍需代表性图像和人工复核，不改变既有 Skill 验证等级。
