# RCE 视觉设计任务调用规范

## 1. 文档定位

本规范定义 Codex Design 在平面视觉与动态视觉任务中使用 RCE（Role–Constraints–Examples，角色—约束—示例）组织任务的方法。

RCE 是任务调用协议，不是独立的视觉风格、生成模型提示词或已经验证的 Skill。它负责把用户需求整理成可执行、可检查的任务契约；具体设计方法、生成步骤、参数与人工审核点仍由共享视觉规范和对应 `SKILL.md` 提供。

适用范围：

- 品牌视觉、海报、KV、版式、字体与图形设计；
- AI 图像生成、图像编辑与静态视觉资产生产；
- 动态海报、Motion Graphics、Logo 动效及静态设计的动态延展；
- 视觉方案分析、提示词编写、设计评审与交付说明。

不适用：纯代码实现、仓库维护、通用办公自动化等不需要视觉设计判断的任务。

## 2. 与 AGENTS 和 Skills 的关系

执行视觉设计任务时，按以下顺序形成完整指令：

1. 读取仓库与当前目录适用的 `AGENTS.md`，确认长期规则、安全边界与文件规范。
2. 使用本规范把当前需求整理成 RCE 任务契约。
3. 读取共享视觉规范，补齐通用设计判断和质量标准。
4. 读取与任务匹配的具体 `SKILL.md`，获得领域工作流、变量、工具路径与审核点。
5. 只读取具体 Skill 明确路由的其他参考资料，不无差别加载无关 Skill。

职责边界：

- `AGENTS.md`：规定长期有效的仓库级或目录级行为。
- RCE：定义本次任务的角色、边界、参考和交付契约。
- 共享视觉规范：定义跨 Skill 的设计语言与质量底线。
- 具体 Skill：定义某类任务的专业做法和可复用流程。

RCE 不得覆盖更高优先级的安全、版权、品牌真实性、仓库规则或具体 Skill 的失败条件。

## 3. 使用原则

### 3.1 先转换需求，再执行设计

不要直接把一句自然语言需求当成完整生产指令。先识别目标、受众、媒介、不可变内容、参考用途和交付形式，再形成 RCE 契约。

### 3.2 角色必须服务于任务

角色描述只保留会改变判断标准的专业能力、视角和职责，不堆砌年限、奖项或空泛头衔。角色不能替代具体 Skill，也不能暗示未经证实的资历。

### 3.3 约束必须可执行、可检查

将约束区分为：

- 硬约束：不得违反，例如准确文字、Logo、品牌色、尺寸、版权、时长、格式和交付路径。
- 软约束：允许在范围内权衡，例如构图倾向、情绪、密度、肌理强度和动效节奏。
- 禁止项：明确不能出现的风格、元素、改写、失真或生成缺陷。

“高级”“年轻”“有艺术感”等抽象词不能单独作为约束，必须翻译为可观察的视觉特征。

### 3.4 示例用于校准，不用于复制

每个示例必须说明参考目的：内容结构、版式、色彩、材质、节奏、输出格式或质量门槛。不得默认复制示例中的受版权保护表达、品牌专属元素、人物身份或文字内容。

没有用户示例时，不得虚构“用户参考”；可以使用本规范的输出模板作为结构示例，并明确这是默认结构。

### 3.5 缺失信息分级处理

- 缺失信息会改变品牌真实性、授权范围、最终尺寸、文字准确性或关键创意方向时，先向用户确认。
- 缺失信息不影响核心方向且可安全推断时，采用最小假设并在输出中列明。
- 不得用长篇问题清单阻断简单任务；只询问会实质改变结果的事项。

## 4. RCE 任务契约

### 4.1 R — Role（角色）

角色至少包含：

1. 专业身份或工作视角；
2. 与本任务直接相关的能力；
3. 需要承担的判断责任；
4. 交付标准。

推荐写法：

```text
角色：
你以【专业身份/视角】完成本任务，重点运用【相关能力】。
你负责判断【构图/层级/字体/色彩/材质/动态等范围】，并交付【交付物】。
输出必须达到【可检查的质量标准】。
```

避免：

- 只写“你是资深设计师”而没有职责；
- 用虚构履历替代设计标准；
- 同时指定多个互相冲突的角色；
- 让角色越权决定未经用户授权的品牌、版权或事实内容。

### 4.2 C — Constraints（约束）

根据任务需要选择以下字段，不要求机械填满所有字段：

| 类别 | 应说明的内容 |
|---|---|
| 目标 | 传播目的、成功标准、希望用户采取的行动 |
| 受众与场景 | 目标人群、观看距离、使用环境、平台 |
| 媒介与规格 | 尺寸、比例、时长、分辨率、色彩模式、文件格式 |
| 不可变内容 | 准确文字、Logo、品牌色、人物、产品、数据、法务信息 |
| 视觉语言 | 风格特征、时代感、图形语法、避免的俗套 |
| 构图与层级 | 第一视觉、阅读路径、留白、主体与辅助元素关系 |
| 字体 | 中英文字体气质、字重、字宽、可读性与授权 |
| 色彩 | 主色、辅助色、对比关系、可访问性与品牌一致性 |
| 材质与光影 | 纸张、颗粒、印刷、金属、玻璃、布料、空间与光线 |
| 动态 | 时长、节奏、转场、循环、静态父设计与避让区 |
| 资产与版权 | 来源、授权状态、允许借鉴与禁止复制的边界 |
| 输出 | 方案数量、文件位置、命名、说明、提示词和可编辑性 |
| 质量门槛 | 必须检查的缺陷、人工审核点和验收标准 |

约束写作要求：

- 一条约束只表达一个判断；
- 尽量使用“必须、不得、优先、允许在……范围内”标明强度；
- 冲突约束必须先排序或向用户确认，不得静默选择；
- 精确文字、Logo、品牌色、人物、产品和数据不得交给生成模型擅自改写。

### 4.3 E — Examples（示例）

每个示例使用以下结构登记：

```text
示例名称/来源：
参考用途：结构 / 版式 / 色彩 / 材质 / 动效 / 输出格式 / 质量门槛
允许借鉴：
禁止复制：
与本任务的差异：
```

使用多个示例时，分别说明各自承担的参考职责；不得把不同示例的所有特征无选择拼接。若示例相互冲突，以用户明确要求和硬约束为准，并说明取舍。

## 5. 标准工作流

### 5.1 输入解析

先提取：

- 项目类型、传播目标和受众；
- 必须保留的文字、品牌和资产；
- 媒介、尺寸、数量、时长和交付格式；
- 参考示例及其用途；
- 用户明确的禁止项与验收标准。

### 5.2 形成 RCE 契约

用简洁字段写出角色、硬约束、软约束、禁止项、示例用途、假设和交付物。契约应短于执行方案，避免重复用户已经清楚表达的内容。

### 5.3 加载专业规则

根据任务类型读取共享视觉规范与一个或多个必要 Skill。若没有匹配的正式 Skill，按共享规范执行，并把新方法保留为实验方向；不得宣称它已经验证。

### 5.4 执行与收敛

先解决目标、构图和层级，再处理字体、色彩、材质与细节。需要给出多个方向时，每个方向必须有明确差异，不得只替换形容词或颜色。

### 5.5 验收与交付

交付前对照 RCE 契约逐项检查：

- 是否完成传播目标；
- 是否违反任何硬约束或禁止项；
- 第一视觉与阅读路径是否清晰；
- 字体、文字、Logo、品牌色、人物、产品和数据是否准确；
- 示例是否只被用于声明的参考目的；
- 生成缺陷、版权风险和未完成的人工检查是否已说明；
- 文件、尺寸、格式、命名和可编辑性是否符合交付要求。

## 6. 推荐输出结构

根据任务规模删减字段；没有内容的章节不要保留空标题。

```text
【任务契约】
角色：
目标：
硬约束：
软约束：
禁止项：
示例用途：
假设与待确认项：
交付物：

【项目定位】
一句话说明设计方向与传播目标。

【视觉概念】
说明核心创意，以及它如何服务目标。

【画面构成与层级】
背景：
主体：
辅助元素：
第一视觉与阅读路径：

【字体与色彩】
标题：
正文：
主色：
辅助色与对比：

【材质或动态】
仅在任务需要时说明。

【执行提示词/制作说明】
给出可直接执行的 Prompt、参数、工具步骤或文件说明。

【质量检查】
已检查：
仍需人工确认：
```

## 7. 快速调用模板

```text
角色：
你以【专业身份/视角】完成【任务】，负责【关键判断】，交付【交付物】。

约束：
- 目标：【传播目标】
- 受众与场景：【受众/平台/环境】
- 硬约束：【准确内容/品牌/尺寸/格式/版权】
- 软约束：【风格/构图/色彩/材质/节奏】
- 禁止项：【不得出现的内容或缺陷】
- 质量门槛：【可检查的验收标准】

示例：
- 来源：【文件/链接/用户提供】
- 参考用途：【只参考什么】
- 禁止复制：【不能照搬什么】

输出：
按【指定结构】提供【方案/提示词/文件/说明】，并列出假设和仍需人工确认的事项。
```

## 8. 简化示例：花卉肌理海报

```text
角色：
你以平面设计师与印刷视觉系统设计师的视角，把用户提供的完整花卉主体转译为可用于海报的平面视觉资产，并交付设计方案与生成提示词。

约束：
- 必须保留花卉主体的完整形态和用户指定配色。
- 视觉语言使用极简几何、纸张颗粒和丝网印刷质感。
- 第一视觉由传播目标决定，不预设主体永远高于标题。
- 不得生成错误文字、额外花卉品种、水印或未经授权的品牌元素。
- 输出需说明构图、层级、字体、色彩、肌理、生成提示词和人工检查点。

示例：
- 用户参考图只用于校准颗粒密度与套色边缘，不复制其独特构图和文字。

输出：
先给任务契约，再给一个主方案；如用户要求对比，再提供差异明确的备选方向。
```

## 9. 禁止事项

- 不得把 RCE 当作替代专业判断的填空表。
- 不得为显得专业而增加不可验证的履历、奖项或品牌背书。
- 不得把所有可能约束无差别堆入简单任务。
- 不得让示例覆盖硬约束、版权边界或真实品牌规范。
- 不得把视觉主体固定为永远的第一视觉。
- 不得在没有实验记录和人工评审证据时，把新提示词框架宣称为已验证 Skill。
- 不得只输出空泛形容词；所有建议必须能转化为设计动作或验收判断。

## 10. 维护规则

- 本文件只维护跨视觉 Skill 共用的任务调用协议。
- 领域特有的方法、模型参数和失败条件应维护在对应 Skill 中。
- 新字段只有在多个任务中反复需要时才加入本规范，避免模板膨胀。
- 若 RCE 的某一部分发展为独立、稳定、可复测的工作流，应先进入 `experiments/` 留存证据，再按仓库晋级流程评审是否创建 Skill。
