# Production Route｜image_generation

适用于 ChatGPT Images 的新图生成、参考创作、局部编辑及多图合成，也供 Codex 生图任务复用专业检查。维护源为本文件；插件内同名文件仅为分发副本。

## 1. 先判断任务和工具

| 任务 | 输入角色 | 工作方式 |
| --- | --- | --- |
| 新建视觉 | 无底图，或仅有主题描述 | 先确定传播目标与构图，再生成 |
| 参考创作 | 风格、构图、配色参考分别指定 | 提取允许借鉴的属性，不把参考作品照搬为底图 |
| 受控编辑 | 明确一张待编辑图；其他图为辅助参考 | 先读图，锁定保留项，限定修改区域和对象 |
| 多图合成 | 底图、插入对象、品牌资产分别编号 | 说明来源、尺度、位置、透视、光线和遮挡关系 |

用户指定 ChatGPT Images 时使用当前宿主实际提供的对应能力。不把 ChatGPT 网页操作、Codex 内置工具和 API 参数混成同一套控制方式；不固定未经核验的模型名、种子、质量档位、次数或像素上限。能力不可用时明确状态，不静默改用付费 API 或其他模型。当前只是写提示词时，不声称已经生图。

## 2. 输入与参数锁定

沿用 [视觉任务与生图提示编写指南](../../Prompt_Framework.md) 和 [参数硬锁](../../shared/parameter-lock.md)，不再维护第二份完整模板。

- 目标：用途、受众、载体、观看距离/阅读任务，以及概念图、排版素材还是最终导出。
- 每张输入图登记：编号/文件名、底图或参考角色、允许借鉴、必须保留、不可复制。未看见文件时不凭文件名猜图。
- 从实际图中读取主体数量、位置、方向、比例、原色、关键结构和文字区；用户指定内容设为 `LOCKED`。
- 记录目标画幅与像素；印刷另记物理尺寸、分辨率、色彩环境和出血。比例与像素矛盾时先明确哪个是准值。
- 编辑任务先列 `KEEP / CHANGE / LOCKED`；局部修改写明区域、对象及边界。要求 pixel-identical 时必须按第 3.1 节确定性合成并验收，不能承诺生成过程绝对不影响选区外。
- 缺省值只补用户未指定项。保色、白底、无字、透明背景、镜头或风格均不能擅自替换用户明确要求。

## 3. 建立可执行提示

先确定 H1/H2/H3、主体与背景关系、留白和文字安全区，再描述形态、材质、光影与颜色。用户的详细提示以整理为主，不额外加入对象、品牌、文案或任意左右布局。

按[提示编写指南](../../Prompt_Framework.md)及其中四类模板组织目标画面与约束；简单任务一段话即可，复杂任务按需分段，不强制角色设定或契约展示。只添加与当前任务有关的排除项。

工具设置与提示正文分开：只有当前接口支持时才设置模型、尺寸、质量、透明背景和导出格式。目标画幅可以写入提示，但必须核对实际输出；不把 API 设置当作网页或 Codex 工具的通用字段。

需要图内文字时，用引号提供准确文案并明确位置、排印和出现次数，允许按用户需求直接生成，逐字复核。需要标准 Logo、精确字体、可编辑排字或严格产品标签时，保留官方资产并采用可控后期；不把生成候选当作已核验品牌终稿。

### 3.1 pixel-identical 与确定性合成

官方明确指出：区域必须 pixel-identical 时，应把确认后的编辑合成回原图，不能仅依靠提示词。工作台据此执行以下生产与验收要求：

1. 保存原图与保护区域定义，先区分“视觉一致”与“逐像素相同”。
2. 生成候选只提供允许修改的内容；在原图上用图层和明确蒙版合成。保护区域直接使用原图像素；羽化边缘必须位于允许修改范围内。
3. 若承诺逐像素相同，保护区不得经历缩放、重采样、整体调色或有损重编码。保留相同像素网格、通道、位深和色彩解释；使用无损验收文件。
4. 重开导出文件，对保护区域逐通道比较像素值（含 alpha）。差异像素数与最大通道差均为 0，才记录该区域 pixel-identical 通过；视觉预览、OCR 或文件大小相同不能替代此项检查。
5. 另需 JPEG、改尺寸或转换色彩时，单独验收其用途，不沿用无损母版的像素一致结论。

这些步骤是工作台的后期验收约定；生成工具返回成功不代表已完成确定性合成。

## 4. 生成、选择与返修

1. 上传或展示本轮真正使用的输入图；本地图片先实际打开检查。
2. 按用户要求的数量生成；未指定时先做一个明确方向，避免无目的批量消耗。
3. 对照输入与硬锁检查候选，而不只凭“好看”选择；标出问题属于主体、构图、字体、颜色、肌理还是生产规格。
4. 将上一轮已确认输出作为下一轮输入，默认每轮只改一个明确变量；确需联动时记录整组范围与原因。重申保留项，先比较结果再补充指令，禁止悄悄换底图。
5. 记录输入/输出版本、实际 Prompt、参数、本轮变量和通过/失败原因；对照原图检查边缘、位置、文字安全区和品牌资产。pixel-identical 按第 3.1 节验收。
6. 发生持续主体漂移或局部无法受控时，回到已确认母版，缩小编辑范围或转入确定性的后期制作；不通过反复整图重生成掩盖失败。

## 5. 验收与 Adobe 交接

| 检查 | 通过依据 |
| --- | --- |
| 需求与主体 | 数量、身份、结构、方向、相对位置和指定构图符合硬锁 |
| 文字与品牌 | 逐字比对文案；官方 Logo/品牌色与标准资产核对，必要时后期替换 |
| 画面 | 无额外对象、残缺边缘、重复结构、假字、水印；纹理尺度和覆盖区域受控 |
| 保留区域 | 对照原始底图/上一个确认版本；按约定检查构图与局部差异 |
| 文件 | 打开实际导出核对宽高、格式、色彩/ICC、位深及 alpha；白底或棋盘格不等于真实透明 |
| 后期 | 需要的图层、矢量路径、字体和可编辑性确实存在；PNG 不冒充 PSD/AI 母版 |

生成后的真实尺寸与目标分开记录。改 PPI 元数据不会增加像素；放大不等于恢复细节。超宽画幅优先重新构图或受控扩展，再按目标检查；不能无说明拉伸主体。

交给 Adobe 时提供：选中版本与输入角色、完整硬锁、准确文案/品牌原件、目标规格、需修正区域、预期图层结构。具体 PS/AI 工作流沿用仓库 `scripts/common/docs/ADOBE_AUTOMATION_GUIDE.md`；当前不能读取该文件时只给实际可执行交接，不声称完成软件处理。

## 6. 输出与状态

- 预览任务：展示实际生成图及本轮判断。
- 项目资产：按用户指定位置或项目既有目录保存；未指定覆盖时使用版本号，不能只留在工具临时缓存。
- 批量：逐张对应文件、版本和验收状态，不以一张样图代替整批完成。
- 简述使用的工具、实际执行提示、输入角色、已检查项与待办。可复用结论回写原规则，未验证方法留在原实验记录。

**PASS**：满足本次约定的交付阶段，硬锁及该阶段文件检查通过。仅约定素材时，素材合格即可完成该阶段。
**WARNING**：概念/生成素材可继续使用，但后期、授权、目标尺寸或人工视觉确认尚未完成。
**FAIL**：错用底图、改写硬锁、主体漂移、文案错误、输出不符，或把生成候选宣称为可编辑/已验证终稿。

状态使用“提示词完成”“生成素材完成”“后期完成”“导出已核验”，并明确尚未执行的环节。
